Chapitre 01

HTML — La structure d'une page

Comprendre ce qu'est une page web avant de la manipuler

Qu'est-ce que le HTML ?

Imagine que tu construis une maison. Le HTML c'est le plan de la maison — il dit "ici il y a un mur, là une fenêtre, ici une porte". Il ne dit pas de quelle couleur sont les murs (c'est le CSS), ni comment les portes s'ouvrent (c'est le JavaScript). Juste la structure.

🏠

La maison et ses trois métiers

HTML = La structure (murs, fenêtres, portes)
CSS = La décoration (peinture, rideaux, meubles)
JavaScript = L'électricité et la domotique (lumières qui s'allument, portes automatiques)

Une page HTML est composée de balises. Chaque balise ressemble à ceci :

HTML 
<!-- A tag opens and closes -->
<p>Hello, I am a paragraph!</p>

<!-- Tags can have attributes -->
<video id="myVideo" src="film.mp4" autoplay></video>
<!--    ↑ attribute     ↑ attribute   ↑ boolean attribute (no value) -->

<!-- A full minimal page structure -->
<html>
  <head>
    <title>My site</title>   <!-- browser tab title -->
  </head>
  <body>
    <h1>Main title</h1>
    <p>A paragraph.</p>
  </body>
</html>
💡
The id attribute

The id attribute gives a unique identifier to a tag. Like a person's name in a room — there can only be one. We'll use it later with getElementById.

Chapitre 02

Le DOM — L'arbre vivant

Comment le navigateur "lit" et représente ta page HTML

Qu'est-ce que le DOM ?

DOM signifie Document Object Model. Quand le navigateur lit un fichier HTML, il le transforme en un objet JavaScript vivant en mémoire. Ce n'est plus du texte — c'est un arbre d'objets qu'on peut lire, modifier, et écouter.

🌳

L'arbre généalogique

Le DOM est organisé comme un arbre de famille. <html> est l'arrière-grand-père. Il a deux enfants : <head> et <body>. Le <body> peut avoir des enfants comme <div>, <p>... Chaque nœud connaît son parent et ses enfants.

Voici comment le navigateur transforme du HTML en arbre DOM :

// DOM tree generated from the HTML below

document
html
body
video id="myVideo" src="film.mp4"
p → "Click to play"
🌟
Pourquoi c'est révolutionnaire

JavaScript peut modifier le DOM en temps réel. Tu peux ajouter des éléments, en supprimer, changer leurs propriétés — et la page se met à jour immédiatement sans recharger. C'est comme ça que les apps web modernes fonctionnent.

Chapitre 03

getElementById — Cibler un élément

La méthode pour trouver précisément un élément dans le DOM

La syntaxe expliquée mot par mot

getElementById est une méthode de l'objet document. Elle retourne une référence vers l'élément dont l'attribut id correspond à ce qu'on lui demande.

📣

L'appel par prénom dans une classe

Imagine 30 élèves dans une salle. Chacun a un prénom unique. Quand le prof dit "Karim, lève-toi", un seul élève répond. getElementById("myVideo") fait pareil : il "appelle" l'élément dont l'id est "myVideo".

JavaScript 
// HTML: <video id="myVideo" src="film.mp4"></video>

// "Grab" this element by its id
const video = document.getElementById('myVideo');
//              ↑             ↑              ↑
// the whole page | the method | the id we search for

// Now "video" holds a REFERENCE to the element.
// We can read its properties:
console.log(video.duration);   // → video duration in seconds
console.log(video.src);       // → the video URL
console.log(video.paused);   // → true if paused

// And call its methods:
video.play();                  // start playback
video.pause();                 // pause
video.currentTime = 0;       // seek to beginning

Décomposition de la syntaxe

Morceau Signification Analogie
document L'objet représentant toute la page HTML La salle de classe entière
. Opérateur "point" — accède à une propriété ou méthode Le "de" : la méthode de l'objet
getElementById get = obtenir · Element = élément · ById = par son id L'appel par prénom
('myVideo') L'argument : l'id qu'on cherche, entre guillemets Le prénom qu'on prononce
⚠️
Piège fréquent — null

Si aucun élément n'a cet id, getElementById retourne null. Appeler null.play() fait planter le programme ! C'est pourquoi on vérifie video.readyState >= 1 avant d'utiliser les propriétés.

Chapitre 04

Les événements

Réagir à ce qui se passe dans le navigateur

Qu'est-ce qu'un événement ?

Un événement est quelque chose qui se passe — un clic, une touche enfoncée, ou dans notre cas : une vidéo qui finit de charger ses métadonnées. Le navigateur "émet" un signal, et on peut écrire du code qui "écoute" ce signal.

🔔

La sonnette de la porte

Une sonnette est branchée à ta porte. Quand quelqu'un appuie (événement), ça sonne (la fonction se déclenche). Tu n'as pas à surveiller en permanence — la sonnette le fait pour toi.

Les événements vidéo essentiels

Événement Quand ça se déclenche Usage typique
loadedmetadata La vidéo a chargé sa durée et dimensions Afficher la durée totale ✅
play La lecture démarre Changer l'icône en ⏸
pause La vidéo est en pause Changer l'icône en ▶
ended La vidéo est terminée Passer à la suivante
timeupdate La position avance (~ 4 fois/sec) Barre de progression
error Erreur de chargement Afficher un message d'erreur

Le readyState — état de chargement

JavaScript 
// readyState: 5 loading levels
video.readyState === 0  // HAVE_NOTHING   — nothing loaded yet
video.readyState === 1  // HAVE_METADATA  — duration & size known ✅
video.readyState === 2  // HAVE_CURRENT_DATA — current frame available
video.readyState === 3  // HAVE_FUTURE_DATA  — can play a bit
video.readyState === 4  // HAVE_ENOUGH_DATA  — can play to the end

// In our component, we check >= 1 to ensure duration exists.
// This is a fallback in case loadedmetadata already fired.
if (video.readyState >= 1 && video.duration) {
  window.ReactNativeWebView.postMessage('duration:' + video.duration);
}

Chapitre 05

addEventListener — Écouter les événements

Brancher une fonction à un événement

La syntaxe complète

JavaScript 
// Basic structure:
element.addEventListener('eventName', functionToCall);

// ─── Example 1: arrow function ───
video.addEventListener('loadedmetadata', () => {
  // This code runs ONLY when loadedmetadata fires
  console.log('Duration:', video.duration, 'seconds');
  window.ReactNativeWebView.postMessage('duration:' + video.duration);
});

// ─── Example 2: named function (same result) ───
function onMetadataLoaded() {
  console.log('Duration:', video.duration);
}
video.addEventListener('loadedmetadata', onMetadataLoaded);
//                                        ↑ NO parentheses! We pass the function
//                                           reference, not call it immediately.

// ─── Multiple listeners on the same element ───
video.addEventListener('pause', () => window.ReactNativeWebView.postMessage('state:paused'));
video.addEventListener('play',  () => window.ReactNativeWebView.postMessage('state:playing'));
❌
Erreur classique — les parenthèses

addEventListener('click', maFonction()) avec parenthèses appelle la fonction immédiatement au lieu de l'enregistrer. Il faut écrire addEventListener('click', maFonction) sans parenthèses pour passer la référence.

Déroulement pas à pas

1

La page HTML se charge

Le navigateur crée le DOM. La balise <video> existe en mémoire.

2

Le script JavaScript s'exécute

getElementById attrape la vidéo. addEventListener enregistre les écouteurs — les fonctions ne s'exécutent pas encore.

3

La vidéo charge ses métadonnées

Le navigateur émet l'événement loadedmetadata. Tous les listeners enregistrés sont appelés automatiquement.

4

La callback s'exécute

video.duration est disponible. On envoie la valeur à React Native via postMessage.

Chapitre 06

La balise <video> et ses propriétés

Tout ce qu'un élément vidéo HTML peut faire

Attributs HTML vs Propriétés JavaScript

HTML — Attributes (in the tag) 
<video
  id="myVideo"       <!-- unique identifier -->
  src="film.mp4"     <!-- video URL -->
  autoplay            <!-- auto-start (boolean flag) -->
  muted               <!-- required for autoplay in most browsers -->
  playsinline         <!-- play inline, not fullscreen (critical on iOS) -->
  controls            <!-- show native browser controls -->
  loop                <!-- loop at end -->
  style="width:100%"  <!-- inline CSS -->
></video>
JavaScript — Properties & Methods 
const video = document.getElementById('myVideo');

// ── READ properties ──
video.duration      // total duration in seconds (e.g. 120.5)
video.currentTime  // current position in seconds
video.paused       // true if paused
video.ended        // true if finished
video.muted        // true if muted
video.volume       // 0.0 to 1.0
video.readyState  // loading level (0-4)
video.src         // video URL

// ── WRITE properties ──
video.currentTime = 30;    // seek to 30 seconds
video.volume = 0.5;        // set volume to 50%
video.muted = true;        // mute
video.src = 'other.mp4';   // change source
video.playbackRate = 2;    // 2x speed

// ── METHODS ──
video.play();    // start (returns a Promise)
video.pause();   // pause
video.load();    // reload the source

Chapitre 07

postMessage — Le pont WebView ↔ React Native

Comment deux mondes isolés communiquent entre eux

Le problème de l'isolation

Un WebView fonctionne dans son propre univers isolé — comme une bulle. Le JavaScript dans la page ne peut pas directement appeler des fonctions React Native, et inversement. On a besoin d'un pont.

📮

La boîte aux lettres

Le WebView et React Native sont comme deux voisins qui ne peuvent pas entrer chez l'autre. Pour communiquer, ils déposent des messages dans une boîte aux lettres. postMessage = déposer un message. onMessage = vérifier la boîte.

JavaScript — Inside WebView HTML 
// window.ReactNativeWebView is injected by react-native-webview

// Send a simple string
window.ReactNativeWebView.postMessage('Hello React Native!');

// We prefix messages to distinguish types
window.ReactNativeWebView.postMessage('duration:' + video.duration);
// → sends e.g.: "duration:120.5"

window.ReactNativeWebView.postMessage('state:paused');

// Or use JSON for complex data
window.ReactNativeWebView.postMessage(JSON.stringify({
  type: 'videoInfo',
  duration: video.duration,
  width: video.videoWidth,
  height: video.videoHeight
}));
TypeScript — React Native component 
// onMessage receives all messages sent from the WebView
const onMessage = (event: any) => {
  const data = event.nativeEvent.data;  // always a string

  if (data.startsWith('duration:')) {
    const duration = parseFloat(data.replace('duration:', ''));
    // parseFloat converts "120.5" (string) → 120.5 (number)
    if (!isNaN(duration)) onDuration?.(duration);

  } else if (data === 'state:paused') {
    setIsPlaying(false);

  } else if (data === 'state:playing') {
    setIsPlaying(true);
  }
};

Chapitre 08

injectJavaScript — Commander le WebView

Envoyer des commandes de React Native vers la page HTML

Le sens inverse

Si postMessage envoie des données du WebView → React Native, injectJavaScript fait l'inverse : envoie du code JavaScript depuis React Native → exécuté dans la page HTML.

🎮

La télécommande universelle

Le WebView est une TV. injectJavaScript c'est la télécommande — tu appuies sur "Pause" depuis ton canapé (React Native), et la TV (WebView) exécute la commande. La TV ne décide pas, elle obéit.

TypeScript — React Native 
const webViewRef = useRef<WebView>(null);

// ─── Pause ───
const pause = () => {
  webViewRef.current?.injectJavaScript(`
    document.getElementById('myVideo').pause();
    true;  // REQUIRED — injectJavaScript must return a value on iOS
  `);
};

// ─── Play ───
const play = () => {
  webViewRef.current?.injectJavaScript(`
    document.getElementById('myVideo').play();
    true;
  `);
};

// ─── Restart from beginning ───
const restart = () => {
  webViewRef.current?.injectJavaScript(`
    const v = document.getElementById('myVideo');
    v.currentTime = 0;
    v.play();
    true;
  `);
};

// ─── Change source SECURELY (via JSON.stringify) ───
const changeSource = (url: string) => {
  const safeUrl = JSON.stringify(url); // escapes quotes & special chars
  webViewRef.current?.injectJavaScript(`
    const v = document.getElementById('myVideo');
    v.src = ${safeUrl};  // safe: no injection possible
    v.load();
    v.play();
    true;
  `);
};
🔐
Sécurité — Injection de code

N'interpolez JAMAIS une URL directement dans le code injecté sans JSON.stringify(). Une URL corrompue comme video.mp4"; alert("Piraté!"); // s'exécuterait dans la page. JSON.stringify() échappe automatiquement tous les caractères dangereux.
